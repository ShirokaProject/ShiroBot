# 宿主内部精简审阅说明

本轮基于 `153588e`。本地 SDK 配置、.NET 11 迁移和其他后续改动不属于本次提交。

## 实际简化

1. **事件分发解除对控制台的依赖。** 原私信路径是 `AdapterEventBridge → 委托 → HostCommandHandler.HandleDirectMessageAsync → HostEventDispatcher`；命令处理器没有增加任何处理，直接原样发布事件。现在所有适配器事件直接进入同一个分发器，移除桥接订阅和 AdapterManager 中的专用私信委托。来源标记、AsyncLocal 实例作用域、队列背压、并发上限、异常记录及停止时排空队列均保留。
2. **命令处理器一次性完成依赖注入。** 解除上述依赖后，不必在加载适配器前创建命令处理器，再两次调用 SetAdapterCommands 并调用 SetPowerControl。现在由现有 DI 容器注册、验证，在启动控制台前解析，构造参数明确列出长期依赖。删除可空依赖字段和生产正常路径不可能到达的“管理器未就绪”分支。没有新增依赖聚合类或服务定位器。
3. **统一适配器变更入口。** 删除 ExecuteAdapterStartAsync 两个纯别名，调用方直接使用原有 ExecuteAdapterMutationAsync。仍是同一个协调器和同一把锁。控制台创建实例直接使用已有的泛型返回值，去掉先定义可空局部变量、再由局部函数赋值的过程；删除操作的停止、删配置、清状态依然在同一临界区内。
4. **合并插件元数据探测转发层。** TryProbePluginInfoFile 直接承载原 TryProbePluginInfoCached 的实现，内部调用使用同一个入口。文件长度、时间戳、脏标记及删除失效规则没有改变，也没有新增程序集加载。
5. **删除小型纯转发。** 控制台直接调用 PluginActions.ListAllAsync；单次使用的命令规范化和宿主更新转发在调用处表达。命令处理器从 ConfigManager.CoreConfigPath 获取核心配置路径，去掉重复传入的字符串。

## 兼容性与保留的边界

- SDK、Models、插件接口和 HTTP 协议没有修改，生产使用的配置、分发器、插件管理器及重载协调器仍是原实例。
- 适配器和插件加载、配置监听、HTTP、自动更新调度、控制台及初始插件加载的先后关系保留。命令对象构造移到依赖就绪之后，其构造本身不启动任务；初始插件就绪门闩仍由分发器等待。
- 配置热重载仍使用原 TOML 监听和可变配置对象；控制台变更令牌保存到同一核心配置文件，并即时影响 HTTP 鉴权。
- 保留适配器卸载的 NoInlining 边界、插件路由闭包工厂、生命周期资源作用域、配置订阅释放和取消处理。这些承担运行时或隔离职责，不能仅按调用次数判断是否多余。
- 本轮检查了启动组装、控制台、适配器事件/重载、插件探测及上下文、更新调度、临时文件清理等相关边界；没有为了统一形式把资源清理与同步逻辑合并成通用框架。
