# 1.0.2

<ReleaseMeta />

宿主、`ShiroBot.SDK`、`ShiroBot.Templates` 和内嵌 Dashboard 均为 1.0.2。SDK ABI 升至 `1.4.0.0`，QQ、Discord、Telegram Model ABI 仍为 `1.0.0.0`。

## 破坏性变更

- 移除 `IPluginServices` 的 `RegisterSingleton<T>()`、`GetService<T>()`、`GetRequiredService<T>()`，`IPluginServices` 不再继承 `IServiceProvider`。用到这些成员的插件需改用 [按名称调用的 JSON 服务或生成的契约](/plugin/interop) 并重新构建，旧 DLL 在新宿主上调用时会失败。
- 插件页面统一为 `Context.Dashboard.AddPage(...)` + `Ui` 组件树。试用过未发布的 `IPluginDashboardProvider` 或路由标签页方案的插件需要改写。

## 新功能

### 生命周期

- `IBotContext.Lifetime` 管理插件的后台任务、循环、定时器和可释放资源，插件卸载时由宿主统一取消和释放。
- 实现 `ILifetimeAwareAdapter` 的适配器每次启动获得新的作用域，停止或因配置重启时清理该次启动登记的资源。

### 插件互调与事件总线

- `Context.Services.Provide` / `CallAsync` 按服务名交换 JSON，`Find` 按前缀发现服务及其描述，`IsAvailable` 检查服务是否可用。
- `Context.Bus` 发布和订阅插件事件。
- 插件间只传递 JSON，不共享对象或程序集；服务和订阅随提供方卸载自动注销，双方可以各自卸载、更新和重新加载。

详见 [插件互调用](/plugin/interop)。

### SDK 契约生成器

- 提供方用 `[PluginContract]` 声明服务和事件；调用方把提供方 DLL 放进 `contracts/`，SDK 在构建时生成契约类型和调用代码，该 DLL 不进入运行时和发布产物。
- `[PluginJson]` 为消息类型生成 JSON 读写代码和 Schema，保留字段默认值并按名称读写枚举。
- 生成器随 `ShiroBot.SDK` 包分发，无需另装。

### Dashboard 插件页面

- `Context.Dashboard.AddPage(...)` 用 `Ui` 组件搭建页面：表格、图片网格、列表、统计、筛选、分页、标签页、按钮和表单。表单可逐字段声明，也可从 record 生成。
- 宿主执行操作前校验组件、条目、字段类型和约束；上传按声明检查 MIME 和大小，单个文件最大 20 MB。
- 所有请求走宿主的 Bearer 鉴权 API，插件无需开放网页路由，Dashboard 也不执行插件提供的 HTML 或脚本。
- 页面显示在插件配置窗口的独立“插件页面”分区，操作即时生效，不依赖配置的保存按钮。页面随插件卸载注销。

详见 [自定义配置页面](/plugin/dashboard-pages)。

### Dashboard 自定义网页

- `AddWebPage` 从插件 DLL 的嵌入资源加载自包含 HTML，在独立来源的沙箱 iframe 中运行，经页面专用的桥接访问插件；API 密钥只保存在父页面。
- 网页用 `request(path, init)` 调用插件的 `DashboardWebPage.RequestAsync`，支持 JSON、文本、multipart 和二进制请求，响应可以带状态码、响应头、文件流和 Range，支持分块传输和取消。
- `DashboardWebJson` 用生成的读写代码或 `JsonNode` 处理 JSON，不影响插件热重载。
- `Confirmations` 声明的操作由 Dashboard 在网页外弹出确认框，网页脚本无法跳过；`StrictDom` 启用 Trusted Types，防止 HTML 注入。
- 请求和资源大小有上限，页面刷新或插件卸载时取消进行中的请求。

### 主程序更新

- Docker 镜像改用与 Release 相同的单文件主程序，Docker 中也能在 Dashboard「关于」页更新主程序。
- 新版本先下载到数据目录的 `host/`（默认 `/data/host`）试运行，能正常启动才替换并重启；需要新的 .NET 运行时或系统依赖时保留旧版本，并提示拉取新镜像。非 Docker 环境同样先试运行再替换。
- 容器启动时，`host/` 中的版本比镜像新且能运行则使用它，否则删除 `host/` 改用镜像，所以拉取新镜像总会生效。

### 每日自动更新

- 插件、适配器、主程序分别开关，默认全部关闭，插件页和适配器页也有快捷开关；每天在 `auto_update_time`（默认 `02:00`，宿主本地时区）执行一次。
- 插件从各自的 GitHub 仓库更新；适配器从适配器市场更新，跳过预发布版本并校验 SHA-256；主程序沿用 Dashboard 的更新流程。
- 可以把单个插件或适配器设为不自动更新：在它的详情面板里关掉“自动更新”，或在配置中心编辑排除列表。
- 默认跳过大版本（如 1.x → 2.0）：不自动安装，只通知 Owner 手动更新，同一个版本只通知一次。版本号无法识别时照常更新。
- 无法热替换的插件或适配器先暂存，默认在更新结束后自动重启宿主完成替换。
- 宿主在执行时间后一小时内都没有运行，当天就跳过；更新引起的重启不会重复执行；单个项目失败不影响其他项目。

### Owner 通知

- 宿主私聊通知 Owner：自动更新的结果和失败、需要重启或已自动重启、主程序需要手动拉取镜像等。没有更新时不发送，重启前先发通知。
- 待确认的更新（来自控制台 `update`、`plugin update` 或插件的 `IUpdater`）可以直接引用通知回复「确认」或「取消」，24 小时内有效。只接受 Owner 的回复，一位 Owner 处理后其他 Owner 的同一条通知失效。控制台的 `confirm` / `cancel` 子命令仍可使用。

### 插件优先级

- 插件按优先级接收事件：数字越小越先收到，同一优先级并发执行。在 `[BotPlugin(Priority = …)]` 中声明，默认 `2`，旧插件行为不变。
- 事件被处理后，优先级数字更大的插件不再收到。命令、前缀、@、回复和带条件的 `MapWhen` 匹配时自动标记为已处理，也可以手动调用 `MarkHandled()`；无条件的 `MapAll` 不标记。把 AI 聊天这类兜底插件的数字设大，命令就不会同时触发 AI 回复。
- 被回复订阅接收的引用回复（如 Owner 确认更新）同样视为已处理。
- 某个优先级 5 秒内没有处理完时记录警告，并继续分发给下一个优先级。
- Owner 可以在插件配置的「路由」页按插件覆盖优先级，或恢复插件默认值。

### 控制台

- 命令按对象分组：`plugin list|market|install|load|unload|update|actions|action` 和 `adapter list|market|install|create|start|stop|reload|config|remove`。`update` 只更新主程序，插件更新改为 `plugin update`。
- `plugin install` / `adapter install` 按市场 ID 安装，`market` 浏览市场，`refresh` 重新拉取市场。
- 移除旧命令 `plugins`、`load`、`unload`、`actions`、`action`、`adapters`、`help`，输入时提示新写法。
- 输入时弹出命令和参数的补全菜单，覆盖在日志上方，不挤动输入行：↑↓ 选择，回车或 Tab 补全，Esc 收起。只输入 `/` 列出全部命令。
- 新增 `dashboard` 命令，在浏览器中打开 Dashboard 并自动登录。
- 控制台、Dashboard 和自动更新使用同一套安装与更新流程。

### 插件操作详细结果

- `PluginActionResult` 新增可选的 `Title` 和 `Details`。设置后 Dashboard 弹出对话框显示，控制台在输入行上方显示。
- 操作抛出异常时，Dashboard 和控制台都显示具体原因；出错的命令不会再让控制台失去响应。

### Dashboard 中选择好友和群

- Owner、Admin 列表和插件路由群组改用选择器，列出运行中实例的好友或群并支持搜索；保存格式不变，不支持读取列表的适配器仍可手动输入。
- 插件配置的 `List<string>` 字段声明 `ConfigField(Type = "users")` 或 `Type = "groups"` 即可使用该选择器。

### 插件监听展示

- 插件配置新增「监听」分区，按群聊、私聊和事件分组列出插件注册的命令、前缀、@、回复、自定义条件和事件。
- `MapWhen` 新增带说明的重载，说明会显示在这里。旧 SDK 编译的插件无需重新编译也能显示，只有没写说明的 `MapWhen` 显示为“自定义条件”。

### 直接编辑 config.toml

- 完整配置页可以切换为「编辑 config.toml」，编辑配置文件的全部内容，包括表单里没有的字段。
- 保存前校验 TOML 并标出错误位置，保存后立即生效；文件在编辑期间被其他地方修改时拒绝保存。
- 插件保留文件中的注释；多实例适配器只编辑当前实例的配置表，不保留注释。没有配置的组件不提供该模式。

### 其他新功能

- `IBotContext.GetHostStatus()` 让插件读取 Dashboard 概览中的宿主信息：版本、运行时长、运行环境、内存、插件数量、消息统计和健康状态等。
- 启动日志和控制台 `api` 命令输出带 `?token=` 的 Dashboard 链接，打开即登录，登录后从地址栏和浏览历史中移除令牌；监听通配地址时链接使用 `127.0.0.1`。
- 设置 `SHIROBOT_DATA_DIR` 并在容器内外挂载为相同路径后，配置、插件、缓存和临时文件都放在该目录，插件交给协议端的文件路径在宿主机上可以直接使用。`container/compose.yaml` 有示例。
- 宿主目录可以用 `SHIROBOT_HOME` 指定，不必与主程序文件放在一起。

## 改进

- 加载兼容性只按 DLL 实际引用的 SDK / Model ABI 判断，不再检查组件声明的 API 版本；插件市场也据此显示兼容要求。
- 适配器列表显示所属聊天平台（QQ、Discord、Telegram），与协议名称（Milky、OneBot 等）区分开。
- Owner、Admin 列表自动去除空白项、多余空格和重复项，避免重复发送通知。
- 主页的“最近错误”1 小时后自动消失，不再一直显示到重启。
- 降低内存占用：回复订阅到期或插件注销时释放回调，慢日志客户端的缓存队列有上限，Avalonia 推迟到首次渲染时才初始化。
- Avalonia 升级至 12.1.4。

## 修复

- 超时卸载的插件延迟清理时，不再误删同 ID 新实例的服务和订阅。
- 提供方返回无效 JSON 时报告 `PluginServiceException`；正在卸载的提供方不再显示为可用。
- 生成的 JSON 代码不再阻止插件卸载；含下划线的枚举名称读写正确。
- 核心配置和适配器接口的错误响应带上可读的 `message`，Dashboard 能显示具体原因；权限条目格式错误时指出是哪一条。
- 模板的 `dev.ps1` 在 macOS 和 Linux 上下载对应平台的主程序并设置可执行权限。

## 新增配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `owner_notifications` | `true` | 私聊通知 Owner |
| `auto_update_plugins` | `false` | 每天自动更新插件 |
| `auto_update_adapters` | `false` | 每天自动更新适配器 |
| `auto_update_host` | `false` | 每天自动更新主程序 |
| `auto_update_time` | `"02:00"` | 自动更新时间（`HH:mm`，宿主本地时区） |
| `auto_update_restart_on_pending` | `true` | 有更新无法热替换时自动重启宿主 |
| `auto_update_exclude_plugins` | `[]` | 不自动更新的插件 ID |
| `auto_update_exclude_adapters` | `[]` | 不自动更新的适配器包 ID |
| `auto_update_skip_major` | `true` | 大版本更新不自动安装，只通知 Owner |
| `[plugin_routes.priorities]` | — | 按插件 ID 覆盖优先级 |

以上配置都可以在 Dashboard 中修改，保存后立即生效。

## 新增 SDK 接口

- 生命周期：`IBotContext.Lifetime`、`IPluginLifetime`、`ILifetimeAwareAdapter`。
- 互调：`IPluginServices` 的按名称调用、服务发现与描述，`IBotContext.Bus`。
- 契约：`[PluginContract]`、`[PluginJson]` 及生成的调用代码和 JSON Schema。
- Dashboard：`IBotContext.Dashboard`、`IPluginDashboard`、`DashboardContext`、`DashboardResult`、`Ui` 组件与表单、`DashboardWebPage`。
- 宿主状态：`IBotContext.GetHostStatus()`、`HostStatus`、`HostRuntimeInfo`、`MessageFrequencyBucket`。
- 路由描述：`MessageRouteDescriptor.Condition` / `ConditionArgument` / `Description`、`MessageRouteCondition`、`EventRouteDescriptor`、`EventRouter.Routes`、`PluginBase.GetEventRoutes()`，以及 `MapWhen` 的带说明重载。
- 优先级：`BotPluginAttribute.Priority` / `DefaultPriority`，`MarkHandled()` / `IsHandled()`。
- `PluginActionResult.Title` / `Details`。

## HTTP API 变化

- 插件页面：`GET /api/v1/plugins/{id}/pages`，`POST .../pages/{page}/render`、`.../events`、`.../upload`，`GET .../files`。
- 好友和群：`GET /api/v1/directory/users`、`/groups`，返回各实例的列表（`entries`）和无法读取的实例（`unavailable`），缓存 1 分钟，`?refresh=1` 强制刷新。
- 原始配置：`GET` / `PUT /api/v1/plugins/{id}/config/raw` 和 `/api/v1/adapters/{id}/config/raw`。`PUT` 需带上读取时的 `revision`，文件已变化返回 `409 config_changed`，格式错误返回 `400 invalid_toml`，没有配置返回 `400 no_config`；配置的 `GET` 响应新增 `raw_config` 表示能否编辑。
- 优先级：插件配置的 `routes` 新增 `priority`、`priority_configured`、`declared_priority`，`PATCH` 时 `routes.priority` 设为 `null` 恢复默认；`GET /api/v1/plugins/list` 的已加载插件新增 `priority`。
- `GET /api/v1/plugins/{id}` 新增 `listeners`，插件未加载时为 `null`。
- 适配器包和实例列表新增 `models`，表示适配器所属的聊天平台。
- `GET` / `PATCH /api/v1/config` 支持新增的配置项。

## 升级说明

- 用到已移除 typed 服务的插件必须迁移并重新构建。使用本版新接口的插件和适配器需要 1.0.2 宿主；其他组件照常按实际引用的 ABI 检查。
- Docker 用户需要手动升级一次到 1.0.2：`docker compose -f container/compose.yaml pull && docker compose -f container/compose.yaml up -d`，之后可以在 Dashboard 中更新主程序。
- 容器默认使用 UTC，自动更新时间也按 UTC 计算；需要本地时间请在 `container/compose.yaml` 中设置 `TZ`，例如 `TZ: Asia/Shanghai`。
- `rebuild-container` 工作流只能重建 1.0.2 及之后的版本。
- 非自包含版需要安装 ASP.NET Core 10 Runtime，建议使用最新的 10.0.x 补丁。
