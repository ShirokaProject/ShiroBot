# ABI 兼容性与版本

## 当前版本

当前源码中的宿主和 `ShiroBot.SDK` 版本均为 **1.0.2**。各共享程序集的 ABI 如下，版本值由仓库根目录的 `Directory.Build.props` 维护。

| 宿主 / ShiroBot.SDK | SDK ABI | QQ Model ABI | Discord Model ABI | Telegram Model ABI |
| --- | --- | --- | --- | --- |
| 1.0.2 | 1.4.0.0 | 1.0.0.0 | 1.0.0.0 | 1.0.0.0 |

产品版本与 ABI 版本用途不同：产品版本标识宿主和 SDK 包，ABI 版本标识程序集公开契约。`ShiroBot.SDK` 包同时包含 SDK 与内置 QQ、Discord、Telegram Model；每个程序集分别维护自己的 ABI。

## 加载兼容规则

宿主按插件或适配器 DLL **实际引用的程序集版本**检查兼容性。对于 `ShiroBot.SDK` 和各内置 Model，必须同时满足：

- 引用的 ABI 主版本与宿主提供的主版本相同。
- 宿主提供的 ABI 版本不低于 DLL 引用的版本。
- 组件引用的每一个 SDK / Model 程序集都通过检查。

例如，引用 `ShiroBot.SDK` ABI `1.4.0.0` 的插件，需要宿主提供主版本为 `1`、版本不低于 `1.4.0.0` 的 SDK 程序集。

宿主检查入口 DLL 及可解析私有依赖的静态引用；运行时动态加载的依赖也受程序集加载检查约束。兼容要求不满足时，组件不会加载，具体原因可在 Dashboard 和运行日志中查看。

SDK 与内置 Model 由宿主统一提供，组件发布产物不携带这些共享 DLL。更新宿主中的共享程序集需要重启；插件或适配器自己的实现程序集按宿主支持的流程热重载。

## 插件市场展示

市场生成脚本从发布 DLL 静态读取 SDK / Model 引用版本和目标框架，Dashboard 据此展示兼容要求，无需在市场条目中手填产品版本范围。

这些信息用于说明组件需要哪些契约和运行时，不表示已经通过运行测试。ABI 版本不能直接换算成宿主产品版本范围，实际加载仍以宿主的程序集引用检查为准。

## 公开契约维护规则

同一 ABI 主版本内，公开契约应保持兼容：

- 不删除、重命名或修改公开成员的签名。
- 不给公开接口添加抽象成员；扩展能力使用默认实现或独立接口。
- 枚举成员显式指定数值，追加成员时保持现有数值不变。
- 不修改位置记录（positional record）构造参数及顺序；扩展数据使用可选的 `init` 属性。
- 不给公开类型追加 `required` 属性。
- 弃用成员使用 `ObsoleteAttribute`，删除需安排在 ABI 主版本变更时。

公开 API 基线位于 `Tests/ApiBaseline`。修改契约后，应验证 API 基线、程序集版本及组件加载行为，并同步更新本页的当前版本表。
